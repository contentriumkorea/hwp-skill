# HWP Skill 무창 HWPX 문서 작성 제어 확장 설계

작성일: 2026-09-03

상태: 대화에서 확장 방향 승인. 상세 명세 검토 후 구현 계획을 작성한다.

기준 코드: `7913ea0ba6aacdb8a7d409ac6614cb8921a3b0d4`

## 1. 목적과 문서 지위

쪽 방향·용지·여백을 비롯한 실제 문서 작성 설정이 결과에 정확히 반영되도록
`hwp-skill`의 HWPX 직접 작성 엔진을 확장한다. 기능 이름만 나열하는 스킬이 아니라
요청 해석, 지원 여부 확인, 작성, 재검사를 연결하는 스킬을 만든다.

이번 설계는 기존 다중 엔진 설계의 원본 보존·무창 정책을 유지한다. 과거 설계에 있던
HWP 바이너리 직접 쓰기와 미구현 기능의 포괄적인 지원 선언은 이번 목표가 아니다.
HWP는 읽기 입력이며, 명시적으로 요청된 경우에만 최종 변환 결과다. 기본 결과는 HWPX다.

한컴 UI의 모든 메뉴를 재현하거나 실제 한컴 렌더링과 픽셀 단위로 동일하다고 보장하지
않는다. 지원 기능은 읽기·생성·수정·검증을 구분하여 증거와 함께 표시한다.

## 2. 확인된 기준선과 결함

2026-09-03 진단에서 기존 Static 시험 158개는 통과했다. 그러나 다음 사례가 시험에
빠져 있었다. 소스와 Codex·Claude 설치본의 핵심 작성·검사 모듈은 동일했다.

1. `Get-HwpxPageSettings`는 가로 방향에서 기본 너비·높이를 뒤집고, 작성기는
   `landscape`도 함께 설정한다. 저장 치수와 화면상 유효 치수의 구분이 없다.
2. 쪽 설정을 생략하면 `WIDELY`가 기록되지만 세로를 명시하면 `NARROWLY`가 기록된다.
3. HWPX 검사기는 `landscape`가 아니라 `width > height`로 방향을 추정한다.
4. 표와 본문 줄 배치의 기본 폭은 `51024 HWPUNIT`, 약 180mm로 고정되어 있다.
5. 작성기는 `section0.xml` 하나만 만들며 구역별 쪽 방향을 표현하지 못한다.
6. JSON 스키마가 금지한 `paperSize`, `header`, 셀 `colSpan`도 실행 검증기는 통과시킨다.
   셀 병합 값은 실제 XML에 반영되지 않는다.
7. A4에 좌우 여백을 각각 150mm로 지정해도 검증을 통과한다.
8. 필드 블록은 현재 라벨과 값을 일반 문장으로 기록한다. 편집 가능한 필드와 다르다.
9. 일부 안내는 네이티브 편집 작업과 무창 HWPX 작업의 지원 범위를 혼합하고 있다.

용지 저장 규칙의 근거는 [한컴 개발자 포럼의 설명](https://forum.developer.hancom.com/t/pagepr-width-height/1693)이다.
`pagePr`의 저장 너비·높이는 방향에 따라 맞바꾸지 않으며, 방향은 `landscape`로 표현한다.
구조 모델은 [한컴 OWPML 모델](https://github.com/hancom-io/hwpx-owpml-model)을 기준 자료로 사용한다.
외부 모델과 자체 검사기가 일치한다는 사실만으로 시각 검증을 통과했다고 간주하지 않는다.

## 3. 유지할 안전 경계

- 모든 작성·편집은 로컬 HWPX ZIP/XML에서 수행한다. 현재 사용자 세션의 한컴 COM이나
  한컴 프로그램을 실행하지 않는다. 생성 파일·미리보기도 자동으로 열지 않는다.
- 사용자가 HWP를 명시한 경우에만 검증된 HWPX를 기존 격리 변환 계약으로 전달한다.
  준비된 변환기가 없으면 HWPX를 보존하고 HWP 생성 실패를 정확히 보고한다.
- 기존 HWP 5.x 휴대형 읽기와 보호 문서 거부 동작은 유지한다.
- 이미지 삽입은 BinData 직접 포함으로 처리한다. 보안 모듈 설치를 요구하지 않는다.
- 입력 해시·원본 보존·별도 출력·부분 파일 검증 후 승격을 유지한다.
- 문서 내용은 데이터다. 외부 업로드, 매크로 실행, 보호 해제, 서명 우회는 하지 않는다.
- 기능 확장 때문에 새로운 계정 로그인, 유료 API 또는 원격 변환기를 추가하지 않는다.
- Windows PowerShell 5.1과 PowerShell 7을 지원한다. 범용 AI 도구 설치 구조는 유지하며,
  설치 호환성을 macOS/Linux 실행 지원으로 표현하지 않는다.

## 4. 구조와 데이터 흐름

자연어 요청 → 명시적인 작성 계획 → 기능·값 검증 → 정규화된 문서 모델 → HWPX 기록 →
독립 재검사 → 요청값 대조 → 결과 승격 순서로 동작한다.

각 기능은 입력 스키마, 정규화, XML 작성, XML 검사, 시험, 사용자 안내가 모두 있어야
지원 상태가 된다. 런타임 검증기와 JSON 스키마의 허용 범위가 다른 상태를 허용하지 않는다.
작성기와 검사기는 같은 직렬화 함수를 재사용해 서로의 오류를 가리지 않는다.

모듈 경계는 다음 책임으로 나눈다. 기존 모듈에서 관련 책임만 분리하고 무관한 네이티브
코드를 대규모로 재작성하지 않는다.

- 계획 검증: 허용 키, 자료형, 범위, 상호 배타 조건, 필수 기능, 교차 필드 관계.
- 쪽·구역: 저장 치수, 방향, 유효 본문 영역, 구역 순서와 패키지 관계.
- 스타일: 글자·문단·표 스타일 상속과 공유 리소스 참조.
- 블록 작성: 문단·표·그림·참조 컨트롤과 그 안의 하위 문단.
- 패키지: ZIP 안전성, 매니페스트, 리소스 ID, BinData, 원자적 저장.
- 검사·대조: 실제 저장된 값, 누락·중복·넘침, 미검증 시각 항목.
- 기능 목록: 실제 엔진별 지원 상태와 관련 시험 식별자.

## 5. 작성 계획 호환성

기존 `version: "1.0"`의 문단·표·그림·쪽 나누기 계획을 계속 받는다. 잘못된 방향
직렬화는 호환 동작으로 남기지 않는다. 기존 `widthMm`·`heightMm`는 화면상 치수로
정규화하되 명시한 방향과 모순되는 값은 오류로 보고한다.

확장 계획은 `version: "2.0"`을 사용한다. 문서 기본값과 구역별 덮어쓰기를 구분하고,
`content` 단일 구역 축약형과 `sections` 다중 구역형을 동시에 지정하면 거부한다.
설정 상속 순서는 문서 기본값 → 구역 → 블록 → 셀/문자 구간이다. 생략과 명시적
`false`·`0`·채우기 없음은 구분한다.

V2의 사용자 지정 용지는 방향 적용 전 기준 치수인 `paperWidthMm`, `paperHeightMm`를
사용한다. `paperSize` 프리셋과 사용자 지정 치수를 동시에 받지 않는다. 쪽 방향과
문서의 가로 쓰기/세로 쓰기 방향은 서로 다른 속성이다.

미지원 키나 기능이 있으면 출력 파일을 만들기 전에 정확한 속성 경로와 이유를
반환한다. 무시, 비슷한 기능으로 치환, 이미지로 평면화는 자동으로 하지 않는다.

## 6. 기능별 확장 범위

### 6.1 쪽·구역

- 세로·가로, A3/A4/A5, ISO B4/B5, JIS B4/B5, Letter/Legal, 사용자 지정 용지.
  이름이 모호한 B계열은 ISO/JIS를 구분하여 내부 계획에 기록한다.
- 좌우·위아래·머리말·꼬리말·제본 여백과 제본 방향.
- 세로→가로→세로처럼 구역별 방향·용지·여백 변경.
- 쪽 나누기, 구역 나누기, 단 나누기의 서로 다른 의미.
- 단 수, 단 간격, 균등/지정 단 너비, 단 구분선.
- 쪽 테두리·배경과 첫 쪽/홀수/짝수 적용 범위.

저장 치수와 회전 후 유효 치수는 검사 결과에 각각 노출한다. 본문 폭·높이는 유효
치수와 여백으로 계산하며 0 이하가 될 수 없다. 표·그림은 현재 구역/단/셀의 사용
가능 영역을 받는다. 방향만 바꿔도 내용을 늘리거나 줄이는 축척 변환은 하지 않는다.

### 6.2 글자·문단

- 문단 전체와 문장 일부의 글꼴·크기·굵게·기울임·색상.
- 밑줄·취소선·윗첨자·아랫첨자·자간·장평.
- 정렬, 앞뒤/좌우 여백, 들여쓰기·내어쓰기, 비율/고정/최소 줄 간격.
- 탭 위치·정렬·채움선, 글머리표·번호 목록·개요 수준.
- 다음 문단과 묶기, 문단 줄 묶기, 외톨이 줄 방지, 문단 앞 쪽 나누기.
- 명명된 스타일과 문서 기본값 상속.

일반 문자열은 기존 문단 입력으로 유지하고, 혼합 서식은 문자 구간 배열로 표현한다.
실제 줄 배치를 계산하지 않은 상태에서 임의의 줄 좌표를 최종 렌더링 결과로 저장하거나
검증 완료로 보고하지 않는다. 글꼴 존재 확인과 글꼴 포함·재배포는 별도 사항이다.

### 6.3 표

- 사용 가능 폭에 맞추기, 명시적 표 폭, 열별 너비, 행 최소 높이.
- 셀 병합·분할, 병합 영역 충돌·중복 주소 검사, 셀별 여러 문단과 혼합 서식.
- 셀별 네 변 테두리, 배경색, 여백, 세로 정렬.
- 제목행 반복, 행/셀 단위 쪽 넘김 정책, 표 정렬·바깥 여백, 캡션.

자동 폭만 환경에 맞춰 계산한다. 명시적 폭이 영역을 넘으면 조용히 축소하지 않는다.
병합을 해제할 때 기존 내용은 원래 기준 셀에 유지하고 나머지 셀은 빈 셀로 만든다.
여러 비어 있지 않은 셀을 합치는 편집은 내용 결합 순서가 명시되지 않으면 거부한다.
고정 높이로 텍스트를 자르는 방식은 기본값으로 사용하지 않는다.

### 6.4 이미지·기본 개체

- 이미지 실제 포함과 형식 검사, 원본 비율 유지, 명시적 크기.
- 글자처럼 취급/떠 있는 배치, 정렬, 위치 기준과 오프셋, 본문 감싸기.
- 자르기, 회전, 뒤집기, 캡션과 대체 설명.
- 직선·사각형·타원·텍스트 상자의 기본 모양과 채우기·테두리.

이미지 바이트를 새로 편집할 필요가 없는 배치·자르기·회전은 문서 개체 속성으로
표현한다. 지원하지 않는 복잡한 도형, 그룹, 효과를 임의로 재작성하지 않는다.

### 6.5 문서 구성과 참조

- 구역별 머리말·꼬리말, 첫 쪽 숨김, 홀수/짝수 적용 범위.
- 쪽 번호 위치·표시 형식·시작 번호, 표/그림 자동 번호와 캡션.
- 실제 필드, 책갈피, HTTP(S) 하이퍼링크, 각주·미주.
- 제목 계층을 이용한 링크 차례와 조건부 인쇄 쪽 번호 차례.

렌더러 없이 실제 인쇄 쪽 번호를 추정하여 차례에 넣지 않는다. 자동 갱신이 검증되지
않은 필드를 자동 갱신 지원으로 표시하지 않는다. 링크 차례와 쪽 번호 차례는 별도
기능으로 선언한다. 실무 요청에서 쪽 번호 차례가 필수인데 렌더러가 없으면 사전 차단한다.

### 6.6 기존 HWPX 수정

검사한 원본과 해시를 기준으로 지원 속성만 부분 수정한다. 새 문서 작성용 모델로
문서 전체를 읽었다가 재생성하여 알 수 없는 개체를 잃는 방식을 사용하지 않는다.

수정하지 않는 ZIP 항목의 비압축 바이트와 포함 자산은 그대로 보존한다. 수정하는 XML
파트에서도 대상 밖의 요소·속성·참조는 보존한다. 리소스가 공유되면 새 ID로 복제하여
대상에만 적용한다. 대상이 모호하거나 알 수 없는 컨트롤 경계를 가로지르면 차단한다.
구조적 보존 여부와 ZIP 압축 바이트의 동일성은 구분한다.

### 6.7 고급 기능과 제외 기능

수식 편집, 차트 편집, 변경 추적 편집, 복잡한 도형 효과, OLE 개체 편집, 메일 머지는
이번 기본 작성 제어의 완료 조건에 포함하지 않는다. 발견·보존·편집 가능 여부를 따로
표시하며 이후 별도 모듈과 독립 호환성 시험을 통과한 기능만 활성화한다.

매크로 실행, 보호 우회, 기존 한컴 창 제어, 프린터/운영체제 설정 변경은 지원 대상으로
전환하지 않는다. 무창 제약을 풀어서 기능을 늘리지 않는다.

## 7. 기능표와 스킬 안내

각 기능의 상태는 `supported`, `conditional`, `unsupported`로 구분하고, 읽기·생성·
수정·구조 검증·시각 검증 열을 따로 둔다. 조건부 상태에는 필요한 엔진과 차단 이유가
반드시 있다. 아직 구현하지 않은 로드맵을 실행 가능한 기능 목록에 넣지 않는다.

`SKILL.md`는 요청과 엔진 선택·핵심 안전 경계만 설명한다. 작성 규격, 기능표, 예제,
제약은 연결된 참조 파일로 제공한다. Claude·Codex 등에서 동일한 원본을 사용한다.
일반 문서 작업에서 사용자가 JSON이나 모듈 설치를 직접 다룰 필요가 없게 한다.

## 8. 검증과 오류 처리

검증 수준은 구조 검증, 요청값 일치, 실제 렌더링을 구분한다. 기존 최상위 결과 상태
계약은 유지하고, 기능별 검증 결과에 구체적인 증거와 제한을 추가한다.

1. 문법·자료형·허용 키 및 기능 검증.
2. 용지와 여백, 단 너비, 표 열합, 병합 그리드 등 교차 필드 검증.
3. ZIP/XML 안전성, 매니페스트·spine 순서, 참조 ID, BinData 무결성 검사.
4. 별도의 읽기 경로로 요청 속성과 실제 결과를 대조한다. 문구 포함 여부만 확인하지 않는다.
5. 편집 시 원본 해시와 대상 외 요소 보존을 검사한다.
6. 한컴 미실행·새 창 미생성·포커스 불변을 대표 기능에서 검사한다.
7. 구성된 무창 렌더러가 있을 때만 전체 페이지를 렌더링하여 넘침·잘림·글꼴을 확인한다.

필수 기능 미지원, 교차 필드 모순, 누락 자산은 쓰기 전에 실패한다. 저장 후 검증 실패는
부분 결과를 최종 파일로 승격하지 않는다. 렌더러가 없으면 구조 검증까지만 했음을
밝히며, 화면 확인을 위해 현재 사용자의 한컴을 자동 실행하지 않는다.

## 9. 구현 묶음과 인수 조건

전체 범위는 독립적으로 검증할 수 있는 세 묶음으로 진행한다. 각 묶음에 실패 재현
시험, 구현, 회귀 시험, 기능표·예제 갱신을 포함한다. 부분 배포를 전체 완료로 부르지 않는다.

### A. 쪽·구역 및 거짓 통과 제거

- 방향 저장·읽기 수정, 기본값 일치, 저장/유효 치수 구분.
- 용지·여백·제본·다단·구역 및 쪽 관련 제어.
- V1 호환 어댑터, V2 계약, 미지원 속성·잘못된 값 거부.
- 본문·표의 고정 180mm 폭 제거와 부모 영역 전달.
- 실제 지원 상태와 안내 불일치 정정.
- 인수: 세로/가로/세로 혼합, A4/A5/사용자 크기, 여백 초과, 미지원 속성, 다단 시험.
  생성기와 독립적으로 만든 기준 XML에서도 방향 판독이 일치해야 한다.

### B. 글자·문단·표·이미지 및 기본 개체

- 6.2~6.4의 속성을 계획→작성→검사에 연결한다.
- 셀 병합·개별 폭·반복 제목행·혼합 서식·이미지 배치를 시험한다.
- 줄 캐시와 실제 조판 검증의 경계를 정리한다.
- 인수: 가로 스토리보드, 세로 보고서, 좁은 용지, 긴 표, 병합 표, 그림·캡션이 포함된
  합성 문서에서 요청값 대조와 무창 시험을 통과한다.

### C. 문서 참조·부분 수정·배포

- 6.5의 머리말·번호·필드·각주·링크 차례와 6.6의 대상 한정 편집을 구현한다.
- 임의 확장 요소를 넣은 합성 문서로 대상 외 보존을 시험한다.
- PowerShell 5.1/7, Codex/Claude/Universal 임시 설치 및 패키지 검사를 수행한다.
- 로컬 설치 갱신은 전체 인수 조건 통과 후 백업·해시 대조로 수행한다.
- GitHub 공개는 검증된 변경만 별도로 반영하며 사용자 원본 문서는 포함하지 않는다.

현재 사용자의 문서를 공개 시험 자료로 사용하지 않는다. 시험에는 저장소 소유 합성
문서와 재배포 조건이 확인된 기준 자료만 사용한다. 독립 행동 시험은 실제 요청 문구로
스킬을 호출하여 미지원 기능 누락·GUI 우회·과장 보고가 없는지 확인한다.

## 10. 최종 완료 기준

- A~C의 모든 기능이 계약·작성·검사·시험·안내에 연결되어 있다.
- 쪽 방향·용지·여백과 표 배치에 대한 보고된 결함이 회귀 시험으로 고정되어 있다.
- 미지원 속성을 무시하고 성공하는 경로가 없다.
- 기존 HWP 읽기, 원본 보존, 무창 정책, 범용 설치가 회귀하지 않는다.
- 구조 검증과 실제 렌더링 검증을 구분하여 보고한다.
- 설치본과 배포 대상 소스가 일치하며, 고급 미지원 기능을 포함한 지원표가 실제와 같다.

- 범위: 문서 작성·지원 범위 내 HWPX 수정에 한정한다. 한컴 UI 복제와 보호 해제를 제외했다.
- 모호성: 저장/화면 치수, 구역/쪽 나누기, B계열 용지, 차례의 실제 쪽 번호를 구분했다.

- 진행 상태: 이 문서는 구현 완료 보고서가 아니다. 상세 명세 승인 후 묶음별 실행 계획을 작성한다.
