# 편집하기 쉬운 빈 문단 간격 방식 적용

2026-09-03 사용자 승인 후 작성 지침과 기본 예제를 변경하고 Codex·Claude 설치본을
백업 후 교체했다. 이번 변경은 실행 엔진을 바꾸지 않고 이미 지원하는 빈 문단과
문단별 글자 크기를 사용하는 방식이다. 앞선 방향·단위 수정도 그대로 보존했다.

## 적용 기준

- 별도 서식 지시가 없는 새 서류는 A4 세로, 공통 줄 간격 160%, 문단 위·아래 0이다.
- 제목·소제목·본문 사이 추가 공간은 `text:""`인 독립 paragraph로 만든다.
  빈 문단의 글자 크기만 조절하며 본문 크기를 여백 때문에 바꾸지 않는다.
- 기본 예제는 6pt/9pt 빈 문단을 사용한다. 고정된 물리 높이의 보증값은 아니다.
- 문단 내부 줄바꿈인 `\n\n`이나 공백 문자를 빈 문단으로 대신하지 않는다.
- 기존 양식과 사용자가 명시한 문단 간격은 보존한다. 기존 문서를 자동 재작성하거나
  표의 모든 셀에 빈 줄을 일괄 삽입하지 않는다.

수정 파일은 `skills/hwp-skill/SKILL.md`, `references/authoring.md`,
`examples/generate-new.plan.json`이다. 기본 V1 예제에 남아 있던 제목 줄 간격 145%와
문단 아래 5mm를 제거하고, 공통 160%/앞뒤 0 및 9pt 빈 문단으로 바꿨다.

## 검증

| 검사 | 결과 |
|---|---|
| 기존 안내로 독립 소비자 5회 | 모두 빈 문단 없이 제목/본문 스타일에 문단 여백 사용 |
| 수정 안내로 같은 요청 5회 | 모두 문단 위·아래 0, 줄 간격 160%, 6pt/9pt 빈 문단 사용 |
| 위 5개 계획 실제 HWPX 작성 | 모두 생성·독립 ZIP/XML 검사 통과 |
| 새 회귀 시험 수정 전 | 기본 예제 2개 실패, 기존 빈 문단 기능 3개 통과 |
| 새 회귀 시험 수정 후 | PowerShell 7/5.1에서 각각 5개 통과 |
| PowerShell 7 전체 Static | 450 통과, 실패 0 |
| PowerShell 5.1 전체 Static 최종 실행 | 444 통과, 실패 3, 제외 3 |
| 5.1 화면 감시만 재실행 | 5 통과, 실패 3; 아래 한계 참조 |
| Codex 설치본, PowerShell 7 | 새 회귀 5개 통과, 소스 41개 파일 해시 일치 |
| Claude 설치본, PowerShell 5.1 | 새 회귀 5개 통과, 소스 41개 파일 해시 일치 |
| 스킬 메타데이터 | `quick_validate.py` 통과 |

새 회귀 시험 `tests/HwpxEditableSpacing.Tests.ps1`은 실제 문서를 생성해 빈 문단의
독립 존재·글자 크기·공통 문단 서식을 검사한다. 빈 문단만 6pt→12pt로 부분 수정해
앞뒤 본문 XML과 원본 파일 해시가 유지되는 것도 확인한다. Windows PowerShell 5.1이
한글 시험 문자열을 CP949로 오해하던 문제는 새 시험 파일의 UTF-8 BOM으로 해결했다.
생성 예제 JSON과 스킬 문서는 UTF-8이며 엔진/API는 변경하지 않았다.

## 화면 감시 검사 한계

5.1의 전체 실행 및 별도 재실행에서 새 최상위 창 또는 포커스 변경이 감지되어 각 3개
검사가 실패했다. 감지 항목은 실행마다 달랐다. 같은 검사에서 새 HWP·Word·Explorer
프로세스 검사는 통과했다. 추가 진단에서도 HWP/Word 신규 실행 0, 한컴 포커스 탈취
false였지만 일반 foreground 변경은 관찰되었다. 해당 변화를 스킬이 발생시켰는지
다른 앱/사용자 활동인지 특정하지 않았으며, 검사 조건을 완화하지 않았다.
따라서 모든 환경에서 화면·포커스 무변경 검증을 완료했다고 주장하지 않는다.
5.1의 제외 3개는 기존 Test-Json 관련 시험이며 PowerShell 7에서는 통과했다.

한컴 GUI/Native 통합 시험은 실행하지 않았다. 빈 문단의 실제 조판 높이, 한글 UI에서
엔터·백스페이스로 편집한 화면 및 인쇄 결과는 시각 검증하지 않았다.

## GitHub 게시 사전 확인

사용자의 GitHub 반영 승인 후 `contentriumkorea/hwp-skill` 저장소와 계정을 확인했다.
게시 직전 PowerShell 7 전체 Static 검사를 다시 실행해 450 통과, 실패 0, 제외 0을
확인했다. `quick_validate.py`와 `git diff --check`도 통과했으며, Codex·Claude 설치본은
각각 저장소 스킬 소스 41개 파일과 SHA-256이 일치했다.

이번 재검사는 위 PowerShell 5.1 화면 감시 실패 이력을 대체하거나 실제 한글 화면의
시각 검증을 의미하지 않는다. 게시 대상은 소스·시험·한국어 문서이며, 사용자 문서와
`tests/output/`의 실행 산출물은 제외한다.
