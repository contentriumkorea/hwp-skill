# 세로 기본값·줄 간격 회귀 수정 검증

검증일: 2026-09-03. 로컬 작성 코드와 Codex·Claude 설치본을 수정했다.
GitHub 게시, main 통합, 사용자 기존 문서 수정은 수행하지 않았다.
실제 증상이 있는 문서는 이번 요청에 첨부되지 않았으므로 아래 원인과 검증은
스킬 코드, 기존 기준 템플릿 및 합성 문서를 대상으로 한다.

## 확인한 원인과 수정

1. **쪽 방향 반전:** 작성기·읽기·부분 수정·독립 검사기가 동일하게 뒤집힌 enum을
   사용했다. 세로는 `WIDELY`, 가로는 `NARROWLY`로 정정했다. width/height는 회전 전
   용지 치수를 유지한다. 생성 함수와 무관한 기존 한컴 템플릿을 기대값 기준으로 삼았다.
2. **문단 단위 혼동:** 현대 `HwpUnitChar` 분기와 구형 호환 분기의 절대 길이 단위가
   다른데 동일하게 기록하고 있었다. 생성 시 `hp:switch`/`hp:case`/`hp:default`를
   구성한다. 14pt 고정 간격은 현대 1400/구형 2800이며, 비율 160%는 두 분기 모두 160이다.
   부분 수정과 재읽기에도 같은 단위 구분을 적용했다. 원시값은 보존하고 물리 mm/pt를
   별도로 제공해 구형 문단 10mm를 20mm로 잘못 보고하던 문제도 막았다.
3. **부정확한 줄 배치 캐시:** V1 생성에 남아 있던 고정 크기·고정 위치의 추정
   `hp:linesegarray`를 모든 새 문서 생성 경로에서 제거했다. 문단 스타일을 기준으로
   문서 엔진이 배치하도록 하며, 정확한 줄 좌표나 쪽 수를 생성 시 추정하지 않는다.
4. **안내 기본값 혼동:** 일반 서류 예제를 A4 세로, 줄 간격 160%, 문단 앞뒤 0mm로
   분리했다. 가로·고정 간격 등 명시된 설정과 기존 양식의 설정은 보존한다.

독립 검사기는 실제 참조되는 문단 스타일의 호환 분기, 단위, 허용 간격 유형과 양쪽
INT32 범위를 검사한다. 미사용 CHAR 스타일 때문에 정상 문서를 거부하지 않으며,
전역 참조·중복 ID 검사는 유지한다. 작성기 값을 재사용해 기대값을 계산하지 않는다.

## 독립 기준

- 저장 방향과 회전 전 치수: `skills/hwp-skill/templates/default.hwpx`의 WIDELY,
  59528×84186 및 본문 폭 51024를 대조했다. 원본 템플릿은 변경하지 않았다.
  회전 여부와 용지 치수의 관계는 [한컴 개발자 답변](https://forum.developer.hancom.com/t/pagepr-width-height/1693)도 확인했다.
- 문단 호환값: 한컴 작성 파일인 [tac-img-02.hwpx](https://github.com/edwardkim/rhwp/blob/e8800c8def63449808a4092798442652ed460552/samples/tac-img-02.hwpx)의
  28개 FIXED 스타일을 대조했다. 14pt 스타일은 현대 1400/구형 2800이다.
- 허용 유형·저장 범위: [한컴 공개 OWPML 모델](https://github.com/hancom-io/hwpx-owpml-model/tree/1453388472c703a4b299a0834f425cdac16644b9)의
  enum 및 signed INT 정의를 확인했다. AT_LEAST는 같은 단위 처리와 회귀 시험으로
  검증했으며 별도의 실제 한컴 작성 AT_LEAST 표본 대조로 표현하지 않는다.

## 검증하지 않은 것

사용자 문제 파일 자체, 실제 한글 조판 화면, 글꼴 대체, 자동 줄바꿈/쪽 수 및 인쇄
결과는 확인하지 않았다. 구조 검사 통과를 실제 한컴 화면의 시각 검증으로 표현하지 않는다.
한컴·Word·탐색기·출력 문서 창을 실행하거나 보안 모듈을 요구하지 않았다.
이미 만들어진 사용자 문서는 자동으로 재작성하지 않는다.
