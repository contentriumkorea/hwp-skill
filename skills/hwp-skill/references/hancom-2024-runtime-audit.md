# 한컴오피스 2024 정적 분석 기록

## 목적과 적용 범위

이 문서는 설치된 한컴오피스 2024의 파일·자동화 인터페이스를 정적으로 살펴본 결과다.
정적 분석에서 함수 이름이나 COM 형식 라이브러리가 발견됐다는 사실은 이 스킬이 해당
기능을 한컴 창 없이 실행할 수 있다는 뜻이 아니다. 실제 지원 범위는 항상
[기능표](feature-support.md)와 실행 환경에서 확인된 기능을 기준으로 판단한다.

분석은 2026-10-18에 수행했다. 설치 폴더의 실행 파일과 형식 라이브러리, 제공된 설치
패키지의 MSI 데이터베이스를 읽기 전용으로 조사하고 REA/Ghidra로 일부 실행 파일의
정적 경로를 확인했다. 한컴오피스, 설치 관리자, COM 서버 또는 변환 후보를 실행하지
않았고 사용자 화면도 열지 않았다.

## 확인된 구성과 버전

| 항목 | 정적 확인 결과 | 의미와 한계 |
|---|---|---|
| 설치된 `Hwp.exe` | 파일 버전 13.0.0.711, x86 .NET Framework 실행 파일 | 메타데이터만 확인. 전체 코드의 동작을 실행 검증하지 않음 |
| 설치 패키지 MSI | 제품 한컴오피스 2024, 패키지 버전 13.0.0.304 | 설치 패키지 버전과 설치된 실행 파일 버전이 다름. MSI를 실행하지 않음 |
| `HwpEngineWrapper.dll` | 혼합 C++/CLI·네이티브 구성, 인터페이스와 P/Invoke 메타데이터 확인 | 이름과 인터페이스만으로 독립 무창 엔진이라고 단정할 수 없음 |
| `HwpAutomation.dll` | x86 네이티브 모듈 | COM 자동화 구성요소의 존재를 확인한 것이며 독립 변환기라는 증거는 아님 |

설치 패키지의 MSI 기능표에는 한글 편집기, 수식, PDF, PDF 변환, 그리기, 글꼴 및 기타
오피스 구성요소가 나열돼 있다. 이는 설치 패키지가 제공하는 기능 구성을 나타낼 뿐,
각 기능의 설치 여부·사용 가능 여부나 무창 자동화 가능성을 보증하지 않는다.

## 자동화 인터페이스 인벤토리

설치된 형식 라이브러리를 등록하거나 실행하지 않고 읽은 결과:

| 형식 라이브러리 | TypeInfo 수 | 함수 엔트리 수 |
|---|---:|---:|
| `HwpObject.tlb` | 255 | 7,668 |
| `HwpAutomation.tlb` | 245 | 7,488 |

이는 타입 라이브러리에 정적으로 기록된 엔트리 수다. 두 라이브러리 사이에 겹치는 API가
있을 수 있고, 엔트리마다 실행 가능 여부·정확한 동작·버전 호환성을 검증한 수가 아니다.
문서/선택·검색, 쪽/구역, 글자·문단 서식, 표/셀, 그림·도형·수식, 주석·변경 추적,
출력·PDF, 보안·보호 및 폼/컨트롤 범주의 이름을 확인했다.

`IHwpAutomation` 형식 정보에는 열기·저장, 텍스트 가져오기/설정, 페이지 텍스트·이미지,
그림 삽입, 액션 실행, 필드·글꼴·표·도형 관련 이름이 있다. 이는 한글 응용프로그램의
COM 자동화 표면이다. 함수 이름이 있다는 이유만으로 한컴 미설치 환경이나 백그라운드
프로세스에서 호출할 수 있다고 간주하지 않는다. 이 스킬은 이를 호출하지 않는다.

## 변환 실행 파일 후보 분석

- `HwpConverter.exe`는 이름에 `Converter`가 있지만, 정적 호출 경로에서 대화상자 초기화
  중 `HwpFrame.HwpObject.2` COM 개체 생성을 요청하는 것을 확인했다. 따라서 독립적인
  무창 변환기로 취급하지 않으며 실행하지 않는다.
- `HwpApi.exe`에서는 API 목록 관련 문자열과 응용프로그램 초기화/메시지 루프 경로를
  확인했다. 문서 읽기·쓰기·변환을 수행하는 비대화형 CLI라고 검증되지 않았으므로
  변환에 사용하지 않는다.
- 다른 변환 후보도 이 감사에서 무창 HWP/HWPX 변환기로 검증되지 않았다.

따라서 설치본에서 **사용 가능한 독립 무창 HWP 변환기는 확인되지 않았다.** HWP 요청은
스킬의 기존 정책대로 실제 격리 변환기를 따로 검증하기 전까지 차단하고 정상 HWPX 작업본을
보존한다. HWPX 직접 작성·이미지 삽입은 한컴 창이나 한컴 보안 모듈을 사용하지 않는다.

## 기능 판정과 미검증 항목

- **관찰:** 파일 버전, MSI 기능 항목, 타입 라이브러리의 타입/함수 엔트리, 일부 네이티브
  실행 경로를 정적으로 확인했다.
- **판정:** COM 인터페이스가 응용프로그램에 의존하므로, 이를 무창 파일 엔진이나 사용
  가능한 변환기로 자동 승격하지 않는다.
- **미검증:** 각 API의 실행 결과, GUI 편집 기능 전체, 설치 구성별 실제 동작, 서식 왕복
  정확도, 외부 플러그인·보안 모듈 동작, 모든 HWP 기능의 무창 실행 가능성.
- **하지 않은 작업:** 한컴 실행, 설치·복구, COM 등록/호출, 보안 승인 모듈 설치·복사,
  HWP/HWPX 샘플 변환 후보 실행.

이 분석은 한컴의 모든 편집 기능을 이 스킬이 직접 제어할 수 있게 만들었다는 주장이 아니다.
AI 에이전트는 정적 API 인벤토리와 실제 검증된 스킬 기능을 구분하고, 미지원 기능을 GUI나
COM으로 임의 우회하지 않는다.

## 재수집 가능한 목록과 추가 대조

2.4.0 개발 작업에서는 REA로 `Hwp.exe`, `Hwp.UxXml.dll`, `HwpEngineWrapper.dll`의
정적 메타데이터와 `Hwp.Dlg.dll`의 PE 리소스 트리를 다시 수집하고 원본 Evidence 묶음을
보존했다. `Hwp.UxXml.dll` SHA-256은
`501770d35f59c147a61a9f04f90f854516d1ee9d045f312ef8c20911e0b1305b`이다.

개발용 수집기가 같은 파일의 내장 XML 14개를 실행 없이 읽어 고유 명령/참조 ID 1,798개와
각각의 출처를 추출했다. 두 타입 라이브러리의 모든 타입/함수 디스크립터도 등록 없이
다시 읽었다. 이 목록에는 상속·중복·UI 전용 명령이 있어 사용자 기능 수로 환산하지 않는다.
수집한 전체 명령은 아직 `inventory-only`이며, 메뉴 전체의 의미·실행 검증 완료를 뜻하지
않는다. 구체적인 직접 지원과 남은 범위는 [기능 대조 대장](feature-audit.md)을 따른다.

함수 본문·호출 경로를 추적했다. 바이너리는 읽기 전용이며 대상 DLL/한컴은 실행하지 않았다.

  `9d6ceab46141c19ba3794642f5fb20df79b209a0bc9c1dbc8213f9882fc65635`:
  Import `0x10004130`, ImportDirect `0x10004090`의 필터 위임과
  `0x10024810`의 `/HWPML/BODY/SECTION`·P/DIV/SPAN/번호 처리 경로를 확인했다.
  가상 호출 29개가 미해결인 함수도 있어 독립 HWPX 엔진으로 판정하지 않는다.
- `HncHDKDll.dll`, SHA-256
  `4d5ccf317e63c1ee240cdb0db84024f889e940ee025e971c738fae1c38e8e66f`:
  `HdkIsHwp90File`→`0x1000fbe0`→`0x10010500`→`0x10013420`에서 ZIP의

  동형 확인 경로가 있다. 이는 형식 인식이며 저장/변환 가능성의 증명이 아니다.

  2016 paragraph/ooxmlchart 등 네임스페이스의 분기 등록을 확인했다.
