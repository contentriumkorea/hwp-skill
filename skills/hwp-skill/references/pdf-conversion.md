# 내장 HWPX → PDF 변환

PDF 납품 요청은 `convert-pdf`로 처리한다. 원본 HWPX를 보존하고 PDF만 새 경로에 기록한다.
한컴·COM·보안 모듈·클라우드 API는 사용하지 않으며 결과 파일도 자동으로 열지 않는다.

## 실행

AI가 프로젝트 안의 짧은 작업 폴더와 출력 경로를 준비한다. `SKILL_ROOT`는 설치 경로로
바꾸고, 아직 없는 PDF 파일명을 지정한다. 경로·모드 선택과 검사는 AI가 담당한다.

```powershell
& 'SKILL_ROOT/scripts/Invoke-HwpSkill.ps1' convert-pdf `
  -LiteralPath '프로젝트/보고서.hwpx' -OutputPath '프로젝트/보고서.pdf' `
  -WorkDirectory '프로젝트/tmp'
```

기본 `-PdfMode auto`는 저장 줄 캐시가 하나라도 있으면 `stored-layout`, 전혀 없으면
`reflow`를 고른다. 캐시가 일부 빠지거나 손상돼 직접 출력이 실패하면 자동 재배치로
숨기지 않는다. 사용자가 재배치를 원하면 명시적으로 `-PdfMode reflow`를 사용한다.
AI가 이 스킬로 방금 작성·수정한 작업본을 PDF로 내보내는 경우에는 계산하지 않은 예전
캐시를 재사용하지 않고 `-PdfMode reflow`를 명시한다. 원본과 동일한 줄바꿈·쪽 수를 요구한
작업에서는 근사 재배치로 대신하지 않고 직접 출력의 지원 여부와 미검증 범위를 알린다.

## 두 출력 경로

| 경로 | 처리 | 실행 조건 | 결과 표시 |
|---|---|---|---|
| `stored-layout` | 동봉 HwpForge가 저장 줄 배치를 재생해 PDF 직접 생성 | 지원 OS의 표준 64비트 CPython 3.9+, 완전한 지원 캐시, 해석 가능한 글꼴 | `Fidelity=stored-layout` |
| `reflow` | 기존 HWPX 문단·표·래스터 그림을 HTML로 옮겨 headless 인쇄 | 현재 Windows의 설치된 Edge/Chrome/Chromium | `Fidelity=approximate` |

두 경로 모두 `NativeLayoutVerified=false`다. 직접 경로도 한컴과 동일한 조판·출력이라는
인증은 아니다. 새 작성 문서는 계산하지 않은 줄 좌표를 만들지 않고 재배치 경로를 쓴다.
PDF를 위해 편집용 HWPX에 HWP5의 예전 줄 캐시를 넣지 않는다.

직접 출력은 기본적으로 플랫폼 설치 글꼴을 찾는다. 필요한 경우 `-FontDirectories`
문자열 배열로 로컬 글꼴 폴더를 명시하면 그 폴더만 사용한다. 글꼴을 찾지 못하면 대체
글꼴로 몰래 바꾸지 않고 차단한다. 한컴 설치 글꼴이나 DLL을 스킬에 복사하지 않는다.
재배치는 브라우저의 글꼴 시스템을 사용하므로 글꼴 대체·줄바꿈·표 분할·쪽 수가 달라질
수 있으며 이 경고를 최종 보고에서 감추지 않는다. 재배치와 `-FontDirectories`를 함께
지정하면 차단한다. `-BrowserPath`는 지원하는 설치 브라우저를 명시할 때 사용한다.

## 보존과 제한

- 입력의 실제 HWPX 시그니처·ZIP/XML 안전 한도와 암호/서명/스크립트 경로를 검사한다.
  원본 읽기 핸들·스냅샷·SHA-256을 유지하며 기존 출력·정션·심볼릭 링크 출력은 거부한다.
- 직접 렌더링은 모든 엔진 경고를 실패로 처리한다. 불완전한 캐시나 미지원 개체는
  원본을 보존하고 중단한다. 새 캐시나 페이지 수를 임의로 만들어 통과시키지 않는다.
- 재배치에서 머리말·꼬리말·각주·번호·수식·벡터·이미지 효과 등의 생략/미지원 경고가
  있으면 최종 PDF를 만들지 않는다. 미사용 기본 번호 리소스와 실제로 비어 있는 쪽
  테두리만 독립 확인 후 누락 경고에서 제외한다. 지원 한계는 기존 [미리보기](preview.md)와 같다.
- 브라우저는 별도 headless 프로세스와 개인 프로필·Windows Job Object로 실행한다.
  자식 프로세스의 `TEMP`·`TMP`만 프로젝트 작업 경로로 지정하며 사용자·시스템 환경변수는
  변경하지 않는다. 운영체제나 설치 브라우저가 자체 관리하는 공용 캐시까지 격리하는 샌드박스는 아니다.
  한컴/브라우저 UI를 열거나 사용자의 실행 중인 앱을 종료하지 않는다. 종료 확인이
  안 되면 완성 출력을 만들지 않는다. 원본에 있는 외부 URL·스크립트를 실행하지 않는다.
- PDF 완성 표식·크기·해시와 원본 해시를 확인하고 검증된 바이트를 새 파일 생성 전용으로
  기록한다. 실패하면 최종 PDF는 만들지 않으며 안전하게 정리하지 못한 작업 경로는 보고한다.
- Windows 브라우저 프로필은 긴 경로에서 실패할 수 있다. AI는 프로젝트 안의 짧은
  `-WorkDirectory`를 지정한다. 임의의 시스템 임시 폴더나 외부 드라이브로 우회하지 않는다.
- PDF의 픽셀 수준 품질·실제 쪽 수가 중요한 작업은 생성한 PDF 자체를 렌더링하여 확인한다.
  HTML 미리보기나 HWPX 검사 결과만으로 실제 PDF 확인을 대신하지 않는다.

HWP/HWT 입력은 먼저 [입력 변환](hwp-input-conversion.md)의 제한을 적용한다. 이것은 PDF
출력 기능이며 최종 HWP 바이너리 출력 변환기를 제공한다는 뜻은 아니다.
