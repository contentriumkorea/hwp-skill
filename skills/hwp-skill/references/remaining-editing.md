# 문단 이동·명명 스타일·셀 대각선

기존 HWPX의 지원 범위를 직접 확장하는 작업이다. 원본을 덮어쓰거나 한컴 창을 열지
않는다. AI가 `inspect`의 주소와 리소스 ID를 확인해 계획을 작성·실행하고 결과를
재검사한다. 사용자가 JSON이나 명령을 직접 작성할 필요는 없다.

## 문단 이동

```json
{
  "type":"move-paragraph",
  "address":{"version":"1.0","sourceSha256":"검사에서 받은 해시","part":"Contents/section0.xml","path":[3],"kind":"p"},
  "targetAddress":{"version":"1.0","sourceSha256":"같은 검사 해시","part":"Contents/section0.xml","path":[2],"kind":"p"},
  "placement":"before",
  "expectedText":"이동할 문단의 정확한 원문"
}
```

`placement`는 `before` 또는 `after`다. 두 주소는 같은 원본의 같은 부모 아래에 있는
서로 다른 문단이어야 한다. 문단의 ID·run별 서식·탭·줄바꿈을 그대로 이동한다.
`expectedText`는 검사에서 받은 원문과 줄바꿈까지 정확히 같아야 한다.

이동 문단은 텍스트 전용이어야 하며 구역 설정 문단을 이동하거나 그 앞에 삽입하지
않는다. 구역/셀/머리말 사이 이동, 연결된 문단 목록, 필드·책갈피·각주·미주가 있는
컨테이너의 이동은 참조를 잘못 바꿀 수 있어 차단한다. 여러 이동은 재검사하며 별도
단계로 처리한다. 동일 부모 교체와 내부 수정은 한 계획에 겹쳐 넣지 않는다.

## 기존 명명 문단 스타일 적용·복제

`inspect`의 `resources.styles`에서 사용자가 말한 이름의 `type:"PARA"` 정의를 찾는다.
동명이거나 정의가 없으면 추측하지 않는다. `styleId`에는 실제 `id`를 넣는다.

```json
{
  "type":"apply-named-style",
  "address":{"version":"1.0","sourceSha256":"검사 해시","part":"Contents/section0.xml","path":[2],"kind":"p"},
  "styleId":0,
  "expectedText":"서식을 적용할 정확한 본문"
}
```

추가 옵션이 없으면 기존 스타일의 문단/글자 리소스를 적용한다. `styleIDRef`와
`paraPrIDRef`, 선택 문단의 모든 직접 run의 `charPrIDRef`를 설정하므로 기존 부분
굵게·기울임 등도 그 스타일로 통일된다. 내용·컨트롤·하위 문단을 평문으로 재작성하지
않는다. 부분 강조 유지가 요청되면 이 통일 동작을 임의 수행하지 않고 범위를 확인한다.

`textStyle`, `paragraphStyle`, `name`, `englishName` 중 하나라도 지정하면 원래 명명
스타일과 필요한 서식 리소스를 복제해 선택 문단에만 적용한다. 기존 공유 정의와 다른
문단은 바꾸지 않는다. `textStyle/paragraphStyle`은 기존 `set-run-format` /
`set-paragraph-format`의 지원 속성을 사용한다. 이름은 최대 256 UTF-16 단위이며
`name`은 공백만으로 지정할 수 없다. 복제본 이름을 생략하면 원래 이름을 이어받으므로
다음 작업에서는 이름만이 아니라 새 검사 ID로 특정한다. 원래 공유 스타일의 전역 갱신,
문자 스타일 및 번호 목록 정의 변경은 지원하지 않는다.

`expectedText`는 선택 사항이다. 지정하면 텍스트 전용 문단만 원문 대조할 수 있다.
컨트롤을 포함한 문단의 텍스트를 추정해 가드를 채우지 않는다.

## 셀 대각선

셀의 `tc` 주소와 지원하는 단순 대각선 정의를 사용한다. 구체적인 선 속성과 제한은
[표 통합 제어](tables.md)의 셀 대각선 절을 따른다. 다른 셀과 공유하는 테두리 정의를
직접 변경하지 않고 복제하며, 셀 안 텍스트·그림·기존 사방 테두리와 배경을 유지한다.

## 실행·검증

모든 작업은 `edit-hwpx`로 실행하며 구조/서식 변경 승인 플래그 `-ApproveAdvanced`를
함께 사용한다. 이 내부 플래그는 사용자가 명시한 편집을 매번 다시 승인받으라는 뜻이
아니다. 매 단계 출력에서 새 주소를 얻고 요청한 저장값·원본 해시·자산 보존을 확인한다.
실제 한컴 글꼴 대체·자동 쪽갈이·인쇄 결과까지 확인했다고 보고하지 않는다.
